## ADDED Requirements

### Requirement: Measurement tasks expose metric entry
The system SHALL distinguish metric measurement tasks from ordinary care tasks and provide an action that opens value entry for the linked metric and plant.

#### Scenario: Open entry from measurement task
- **WHEN** user opens a due measurement task for "Water level"
- **THEN** the task identifies the metric and unit and lets the user record a correctly typed value

### Requirement: Required measurement gates task completion
When a linked rule requires measurement, the system SHALL complete its task only after a valid new measurement is persisted. Canceling entry, entering an invalid value, or failing to persist the value SHALL leave the task incomplete. When measurement is optional, the user SHALL be able to complete directly or record a value and complete.

#### Scenario: Required value completes task
- **WHEN** user records a valid value from a required measurement task
- **THEN** the measurement is persisted, the task completes, and its next due date is computed from the measurement timestamp

#### Scenario: Required entry is canceled
- **WHEN** user cancels value entry for a required measurement task
- **THEN** no measurement or completion is recorded

#### Scenario: Optional task completes without value
- **WHEN** user completes an optional measurement task without entering a value
- **THEN** the completion is recorded without adding a measurement

### Requirement: Metric alert tasks link to metric context
An alert-generated care task SHALL display the metric name, latest value, unit, and warning reason and SHALL navigate to that metric's history and entry controls.

#### Scenario: Open alert task
- **WHEN** user selects a care task generated by an out-of-range nutrient measurement
- **THEN** the app opens that plant's nutrient metric with the alerting value and target criteria visible
